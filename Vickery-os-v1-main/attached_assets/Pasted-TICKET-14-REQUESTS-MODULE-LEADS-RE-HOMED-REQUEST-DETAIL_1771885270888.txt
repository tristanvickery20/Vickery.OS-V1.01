REQUEST STATUS SYSTEM (from your original spec)
Order:
Lead -> Quoted -> Scheduled -> In Progress -> Complete -> Invoiced -> Paid -> Closed

Allowed transitions (server validates):
- Any status can only move forward (no backward moves in MVP)
- Scheduled / In Progress require deposit gate pass
- Complete requires: scheduled_date OR at least one visit scheduled (MVP choose one rule)
  AND time entries logged (minutes > 0) OR admin override
- Invoiced requires: status == Complete first
- Paid requires: invoiced_amount > 0 (if you don’t have invoiced_amount on Requests yet, add it ONLY if already present in your old Leads model; otherwise treat Paid/Closed as “later” and show placeholders)
- Closed requires: paid_amount >= invoiced_amount (same constraint)

DEPOSIT GATE (AUTHORITATIVE)
Triggered when:
- deposit_required == true
- (deposit_received is empty or 0)
- deposit_override != true
Blocks:
- Changing status to Scheduled or In Progress
- Any scheduling endpoint that implies a schedule (Visits comes in Ticket 16, but we still gate status moves here)

When blocked:
- Return HTTP 409 with:
  { ok:false, code:"DEPOSIT_REQUIRED", message:"Deposit required before scheduling." }
- Write audit entry:
  action="BLOCKED_DEPOSIT_GATE"
  entity_type="request"
  entity_id=requestId
  note includes attempted transition

DELIVERABLES (SERVER)

1) GET /api/requests (auth)
Query params:
- q (search)
- status (exact or "all")
- limit (default 200 max 500)
Return list of request rows augmented with:
- client_name
- property_address (single line)
- deposit_gate_blocked (boolean)
- sort by updated_at DESC (fallback created_at DESC)

2) POST /api/requests (auth) — minimal create
Body:
{
  client_id,
  property_id,
  summary,
  lead_source (optional),
  deposit_required (bool default false),
  estimated_value (number optional)
}
Behavior:
- validate required fields
- create id REQ-{timestamp}
- status_code default "Lead"
- deposit_received default 0
- deposit_override default false
- created_at/updated_at now
- append to Requests sheet
- audit CREATE_REQUEST
- touchClient(client_id)
- respond with created request

3) PATCH /api/requests/:id (auth) — update fields
Allows:
- summary
- lead_source
- deposit_required
- deposit_received
- deposit_override
- estimated_value
- status_code (status transition)
Rules:
- When status_code included:
  - validate forward-only
  - enforce deposit gate for Scheduled/In Progress
  - enforce Complete gate (minimum: require at least one Time entry minutes>0 for requestId OR allow if deposit_override==true and include admin_override flag in request; simplest is require minutes>0 for MVP)
- Write per-field audit entries OR one combined audit (acceptable):
  - action="UPDATE_REQUEST"
  - include field, old_value, new_value
- Always update updated_at
- touchClient(client_id)

4) GET /api/requests/:id (auth) — detail
Return:
- request row
- client { id, name, phone, email }
- property { address_line1, city, state, zip }
- time summary:
  total_minutes (sum Time.minutes where lead_id == requestId OR if your Time still uses lead_id)
- expense summary:
  total_expenses (sum Expenses.amount where lead_id == requestId)
- costing preview (computed, never stored):
  labor_cost = (total_minutes/60)*labor_rate_tech
  expense_cost = total_expenses
  total_cost = labor_cost + expense_cost
For revenue/gross profit:
- For now revenue = estimated_value OR 0 (MVP)
(Real revenue will come from quotes/invoices later.)
