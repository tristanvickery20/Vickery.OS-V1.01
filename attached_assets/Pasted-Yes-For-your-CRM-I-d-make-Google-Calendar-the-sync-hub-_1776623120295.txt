What I’d build

2) Make every “thing” in CRM one of only two objects

Do not have 8 different weird scheduling systems.

Use only:

Event

Has a start and end time.
Examples:

No hard time unless assigned.
Examples:

* call customer back

Then a task can become:

That is the cleanest structure.

5) Sync rules

Use these exact rules:

CRM → Google Calendar

When created or changed in CRM:

* create/update matching Google event
* store Google event ID in CRM
* set reminders automatically
* keep title standardized

Example title format:

* Estimate – Smith – 123 Main
* Job – Panel Swap – Johnson
* Callback – Williams
* Meeting – Supplier

Google’s API supports event creation, reminders, push notifications, and sync patterns that help keep a local database aligned without duplicating events.  ￼

Google Calendar → CRM

Do limited reverse sync only.

Good reverse sync:

* if you move a CRM-created event on your phone, CRM updates
* if you mark yourself busy with a personal event, CRM can read that for availability
* if an event is deleted on phone, CRM asks whether to unschedule or restore

Bad reverse sync:

* random personal events creating jobs in CRM
* all calendar edits changing business records with no safeguards

So:

* business calendars = two-way for CRM-owned events
* personal calendar = read-only for availability
