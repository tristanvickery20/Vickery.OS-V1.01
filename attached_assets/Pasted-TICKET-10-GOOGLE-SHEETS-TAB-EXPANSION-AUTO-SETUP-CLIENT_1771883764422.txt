WHAT TO IMPLEMENT

1) Centralized Sheet Utilities (server-side)
Create or improve a single module that provides:
- getSheetsClient(): returns an authenticated sheets client
- ensureTabExists(spreadsheetId, tabName): creates sheet if missing
- readHeaderRow(spreadsheetId, tabName): returns header array from row 1
- ensureHeaders(spreadsheetId, tabName, requiredHeaders):
    - if sheet empty -> write requiredHeaders into row 1
    - if header row exists -> append any missing headers to the end
    - do NOT remove existing columns
    - do NOT reorder existing columns
- ensureConfigDefaults(spreadsheetId):
    - ensures Config tab exists
    - ensures headers: key, value (if Config is empty, seed headers)
    - upserts defaults if keys missing

Idempotency: Server can restart 100 times with no header duplication.

2) Startup Auto-Setup Hook
On server startup (index.js/server.js), call a single function:
- ensureCrmSheetSetup()
This function:
- ensures ALL tabs listed above exist
- ensures headers for each tab
- seeds Config defaults
- logs a concise summary once (e.g. “Sheet setup ok: created tabs [..], added headers [..], seeded config [..]”)

3) Backward Compatibility (Do NOT migrate data in Ticket 10)
- Do NOT attempt to move data from Leads -> Requests.
- Do NOT change existing endpoints.
- This ticket only adds schema + setup infrastructure.

4) Safety + Error Handling
- If Sheets API fails, server should still start but log the error loudly:
  - Option A (preferred): fail hard if SHEET_ID missing, because CRM depends on it.
  - Option B: if your app already runs without Sheets in dev, keep existing behavior.
Choose whichever matches existing code patterns (DO NOT introduce new env expectations if not already used).
- Never write over existing data rows—only row 1 (headers) and Config upserts.

IMPLEMENTATION DETAILS (DO THIS)
A) Detect if a tab exists
- Use spreadsheets.get to list sheets by title OR attempt read and catch 404-like errors.
- If missing, create with spreadsheets.batchUpdate addSheet request.

B) Writing headers
- Use values.update to set row 1:
  range: `${tabName}!1:1`
  values: [requiredHeaders]
- When appending missing headers:
  - read current headers
  - compute missing = requiredHeaders not in current
  - if missing -> update range starting at next column index on row 1 OR rewrite row 1 with current + missing (safe).
  - Do not duplicate.

C) Config defaults upsert
- Read Config rows (A:B)
- Build map key -> row index
- For each default key, if missing:
  - append a new row [key, value]
If existing, do nothing.
