==================================================
INVOICE GENERATION LOGIC
==================================================

This is critical.

When a tech or office user presses Generate Invoice, the system should auto-build the invoice from the existing job/quote snapshot data.

Preferred logic:
1. start from approved quote snapshot / job snapshot
2. convert snapshot services into invoice line items
3. preserve the original snapshot pricing as the original invoice baseline
4. calculate subtotal, tax, deposit/paid, and original total
5. create the invoice record
6. render both digital and print versions from the same data
7. allow controlled edits only where appropriate

Important:
- original invoice numbers and original totals should remain preserved
- do not allow sloppy overwriting of source data
- if a field change happens, create a change-order entry and revised total
- final customer invoice should show the revised total cleanly, but still preserve auditability

==================================================
CHANGE ORDER LOGIC
==================================================

This must be handled cleanly.

Real-world context:
The office may print an invoice before the tech leaves in the morning.
Later in the field, something may change.
The tech may need to add labor/material or reduce scope.
The paper version must have room to write this.
The digital system must capture it cleanly later.

Implement change orders like this:
- invoice has original_total
- change orders are separate records
- revised_total = original_total + sum(approved change orders)
- do not overwrite original_total
- keep audit history

Crew experience:
- tech opens invoice
- taps Add Change Order
- enters brief description
- enters amount
- chooses plus or minus
- optionally indicates taxable or not
- revised total updates immediately
- tech can save it with minimal typing

Printable version:
- dedicated handwritten change-order box
- fields for description, amount, approved by, initials, date
- enough room to write legibly

Digital version:
- clear “Change Order” section
- show original amount, change amount, revised total
- do not make it confusing
