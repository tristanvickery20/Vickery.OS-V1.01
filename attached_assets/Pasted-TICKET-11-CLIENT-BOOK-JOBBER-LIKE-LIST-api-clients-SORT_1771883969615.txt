     - limit (number optional, default 200, max 500)

     id
     name
     phone
     email
     status_code
     last_activity_at
     job_description
     most_recent_property: { id, address_line1, city, state, zip }

   - Filter pills or dropdown for status
   - Main list of clickable rows
   - Preserve scroll position when navigating back from detail (store in sessionStorage)
4) Visual status system:
   - Shared status map (frontend constant in clients.js for now):
     active -> label “Active” dot blue
     awaiting_response -> “Awaiting Response” dot gray
     scheduled -> “Scheduled” dot blue
     in_progress -> “In Progress” dot blue
     awaiting_payment -> “Awaiting Payment” dot yellow
     overdue -> “Overdue” dot red
   - Unknown -> label = status_code, dot gray
5) Click row navigates to:

B) SERVER: /api/clients endpoint
Route: GET /api/clients (auth required)
Implementation steps:
1) Load clients = readTab("Clients")
2) Load properties = readTab("Properties")
3) Build lookup by client_id -> properties[]
4) For each client, attach most_recent_property:
   - Prefer primary property (is_primary truthy)
   - Else use the property with latest updated_at or created_at
   - Else null
5) Filtering:
   - status: if provided and not "all" -> exact match on client.status_code
   - q:
     - search across:
       client.name
       client.phone
       client.email
       client.job_description
       property.address_line1
       property.city
       property.state
       property.zip
     - simple substring match, case-insensitive
6) Sorting:
   - sort key = last_activity_at else updated_at else created_at (date compare)
   - DESC
7) Limit:
   - default 200
   - cap 500
8) Response JSON:
   { ok: true, clients: [...] }
