VE OS ALIGNMENT SOURCE

This repo is the CRM/operating system for Vickery Electric, a launch-stage residential electrical service business.

The purpose of VE OS is not to be a generic CRM. It is the operating command center for the business.

The system must reduce chaos, protect profit, enforce process, preserve records, and make the business easier to scale.

The owner is not a coder. Build practical, visible, working features. Do not make vague backend-only changes that cannot be verified in the UI.

Before changing code, read and preserve:
- docs/VE_OS_ALIGNMENT_SOURCE.md
- docs/VE_OS_SCOPE_MAP.md

CURRENT TASK

Add a simple ReferPro-style referral system inside the existing Marketing Hub.

This is NOT a paid third-party integration.
This is NOT AI personalization.
This is NOT a complex campaign engine.
This is a simple, clean referral tracking + personal referral link + employee QR/card stack + reward dashboard system that works with the current Google Sheets-backed app.

The owner wants:
1. Personal referral links for customers.
2. Referral cards/QR links that feel natural and simple for older customers.
3. Instant/automated reward workflow as much as possible without paid third-party services.
4. Employee-specific QR/card stack so each employee can hand out their own referral card.
5. Referral Dashboard inside the existing Marketing Hub.
6. Separate review and referral asks so the customer is not overloaded.
7. No paid third-party services. No new external APIs unless already present/free. No paid dependency.

Use:

SECTION D: REWARD QUEUE

Create a queue that shows only referrals needing owner action.

Buckets:
1. New referral submitted
2. Referred job booked
3. Referred job completed
4. Reward ready
5. Paid
6. Disqualified

Reward logic:
- Default reward amount is $50.
- Large project reward amount is $150.
- A job is “Reward Ready” only after the referred job is completed and paid OR manually marked reward-ready by owner.
- Do not automatically send money through a paid provider.
- “Instant/Automated reward” means:
  - The CRM automatically calculates that a reward is owed.
  - The CRM moves it to Reward Ready.
  - The CRM provides a one-click copy payout message.
  - The CRM records payout method and payout date when owner marks paid.
  - The CRM can send an SMS using existing sendSms only if the repo already has working SMS support.
  - If SMS is not configured, it should log the action and show copyable text.

Payout methods:
- Zelle
- Cash App
- Check
- Direct deposit
- Other

Do not collect bank account data in this task.
Direct deposit should be just a payout_method label for now, not actual ACH.
